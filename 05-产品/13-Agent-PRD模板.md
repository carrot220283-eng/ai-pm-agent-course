# 13 Agent PRD 模板

> **一句话结论**：Agent PRD 和传统 PRD 最大的差别，是你要为「**它行为的不确定性**」写规格，而不是为功能写规格。判断标准只有一条：工程拿着这份文档，能不能在没问你情况下决定「它什么时候停、什么时候必须问人」。

---

## 一、为什么 PM 要懂这个

评审会。你花两天写了八页 PRD：功能清单、交互稿、验收标准，一样不少。工程翻到第 3 页，问了一个问题：

> 「工具查不到数据的时候，它该说什么？」

文档里没有。你说：「就说没查到吧。」

上线第二周，客诉来了：用户问发票，系统里没有记录，它编了一个发票号，还带格式，客服信了，拿去回复客户。当天 11 起同类投诉（示例）。

这不是模型坏，是 PRD 少了一行字。空结果时模型只有两个选择：说没有，或者编一个。**你不写，它就自己选**——而它天然倾向后者，因为在训练里「给出一个答案」被奖励过。

同一版加了一句话：「工具返回空时必须如实告知，不得推测。」编造类投诉从每周 11 起降到 2 起（示例）。一行字，一次发版。

传统 PRD 写「功能应该怎样」；Agent PRD 还要写「它在什么情况下必须停下来」。前者决定它能不能用，后者决定它会不会闯祸。

---

## 二、机制 / 方法

| | 传统 PRD | Agent PRD |
|---|---|---|
| 规格对象 | 功能与交互 | 行为与边界 |
| 关键句 | 「点击后展示列表」 | 「查不到时说什么、第几步停、谁签字」 |
| 验收方式 | 对照原型走一遍 | 对照 trace 与评测集跑一遍 |
| 最大风险 | 做出来不是用户要的 | 做出来了，但它在你没写的地方自己决定 |

打个比方：传统 PRD 像给厨师的菜谱，步骤固定、成品可预期；Agent PRD 像给代驾的**授权书**——路线它自己选，但你必须写清：不能上高速、超过 200 元先打电话、到不了怎么办。

下面这份模板可以直接复制进文档。每节写的是**填好的示例**，把具体值换成你的，就是你的 PRD。

```markdown
# Agent PRD：销售跟进邮件助手
版本 v0.1 ｜ 作者 ｜ 更新日期 ｜ 评审人

## 1. 目标与非目标
目标：销售写一封客户跟进邮件，从 7 分钟降到中位数 90 秒。
非目标：本期不做自动发送；不覆盖售后工单；不承诺「客户一定回复」。

## 2. 用户与场景
主用户：一线销售，每天 20–40 封，现在每封 6–8 分钟。
真实问法（原话，不要润色）：
- 「上次跟王总聊到报价，帮我接着写」
- 「这客户三个月没回了，怎么开口」
- 「把上周的会议纪要变成跟进邮件」

## 3. 能力边界
能答：客户往来记录、报价历史、产品资料范围内的问题。
不能答：合同条款解释、折扣审批、其他销售名下的客户。
必须拒答：承诺价格与交期、评价竞品、导出客户联系方式、代替客户确认合同、给出折扣或返点。

## 4. 系统结构
形态：Agent（只读），最多 6 步。
路径：查客户 → 取近 90 天往来 → 生成草稿 → 自检（客户名/金额/称呼）→ 输出
失败分支：查不到客户走兜底；自检不过重写一次，仍不过转人工。

## 5. 工具清单
| 工具 | 给模型看的描述（含什么时候不要用） | 权限 | 空结果/失败返回 |
| search_customer | 按客户名或公司名查；只查当前账号有权看的客户；用户没给名字时先问，不要猜 | 只读 | 「未找到，请让用户确认客户名」 |
| get_threads | 取该客户近 90 天邮件与工单，返回标题加摘要 | 只读 | 「该客户暂无往来记录」 |

## 6. 停机与兜底
max_steps：6；单次超时：20 秒；同一工具同参数 2 次即停。
空结果文案：「没有查到这个客户的往来记录。你可以手动填写上次沟通要点，或转人工。」
人工入口：第 2 次失败后出现；承诺 30 分钟内响应。

## 7. 上下文与记忆
进上下文：最近 3 轮对话 + 检索 top 5（每条不超过 500 字）。
不进：全部历史邮件、其他客户数据、内部报价底线。
长期记忆：记客户称呼偏好与常用落款，保留 90 天，用户可在「设置-数据」查看和删除。

## 8. 成本与延迟预算
单次上限：0.05 元；P95 首字 2 秒、完整 8 秒；每人每日 50 次。
超预算：降级到小模型，再不行只检索不生成，最后提示稍后。
计量口径：输入加输出 token 加工具调用，不含重试。

## 9. 评测与门禁
考题 30 题：高频 15、边界 10、拒答 5。
通过线 90%；编造客户名、金额、承诺，0 容忍。
否决人：销售运营负责人（姓名），签字才可上线。

## 10. 灰度与回滚
5% → 20% → 50%，每档观察 24 小时。
观察：采纳率、修改率、转人工率、P95、单次成本、投诉。
回滚条件：采纳率低于 25%，或编造类投诉 1 起；开关关闭，1 分钟内生效。

## 11. 依赖与风险
依赖：CRM 接口、邮件检索服务、模型供应商。
风险：供应商涨价或限流、客户数据权限越界、邮件内容合规。
缓解：双供应商、只读权限、发送前人工确认、内容留存 180 天备查。
```

| 节 | 为什么必须有这一节 | 填空示例（怎么换成你的） |
|---|---|---|
| ① 目标与非目标 | 没有非目标，需求会自己长回来，最后被砍的是验收标准 | 把「7 分钟 → 90 秒」换成你的现状与目标，必须是一对数字 |
| ② 用户与场景 | 三条原话决定评测题长什么样 | 去工单或群里抄三句真实提问，别自己写 |
| ③ 能力边界 | 不写拒答，模型会用最流畅的方式越权 | 拒答至少 5 条，每条说清「为什么不能答」 |
| ④ 系统结构 | 没有步数上限，就没有成本上限 | 画成 3–7 个节点，标出哪一步失败就进兜底 |
| ⑤ 工具清单 | 描述写歪，模型就乱调 | 每个工具补一句「什么时候不要用」 |
| ⑥ 停机与兜底 | 决定它会不会编、会不会无限重试 | 三个值：max_steps、超时、同一调用重复几次即停 |
| ⑦ 上下文与记忆 | 记什么、记多久、能不能删，是合规问题 | 写清「不进什么」，比写「进什么」更重要 |
| ⑧ 成本与延迟 | 没有单次上限，一次重试能烧掉一天预算 | 单次上限 + P95 两个数，写死 |
| ⑨ 评测与门禁 | 没有否决人的门禁是装饰 | 题数、通过线、零容忍项、一个真名 |
| ⑩ 灰度与回滚 | 回滚条件不写成数字，出事时没人敢拍板 | 从 5% 起，写清「低于多少就关」 |
| ⑪ 依赖与风险 | 依赖项就是你的单点故障清单 | 列出供应商、接口、权限三类各一条 |

**如果只改三处**：⑤ 工具描述写歪，模型就乱调；⑥ 空结果没文案，它就编；⑨ 没有否决人，门禁就是一张纸。这三节最容易被当成「工程细节」跳过，也最能救命。

### 坏 PRD 与好 PRD

同一个需求（客服工单总结），两段写法：

```
用大模型对工单做智能总结，提升客服效率。
支持自动生成摘要、提取关键信息。
要求准确、稳定、响应快。
上线后根据用户反馈持续优化。
```

```
客服在工单详情页点「总结」，P95 3 秒内得到不超过 5 行的摘要。
摘要须含：问题、已尝试方案、当前状态、下一步。
不做责任判定，不替代原文；与原文冲突时以原文为准，并标注「AI 生成」。
客服可直接复制，灰度第 4 周复制率不低于 50%（示例）。
评测 30 题，事实错误 0 容忍；否决人：客服运营负责人。
```

差别不在文采：好 PRD 的每一句都能被验证——时间、比例、边界、签字人。坏 PRD 的每一句都对，但没有一句能被验收。

## 三、产品视角：这条技术决定了什么决策

1. **你写的是行为规格，不是功能清单。** 标准：每一条都能在 trace 里被验证（它第几步停的、调了什么）。代价：写不出行为规格，验收只能靠「感觉还行」。
2. **三个数字必须落在文档里：max_steps、P95、单次成本上限。** 代价：缺一个，规模化时会以你无法解释的方式变慢或亏钱。
3. **拒答清单比能力清单重要。** 标准：至少 5 条「必须拒答」，每条能说清理由。代价：不写，模型会用最流畅的方式越过权限。
4. **否决人要写名字，不写角色。** 标准：一个具体的人加一条明确的线。代价：没人签字，出事时第一个被问的是你。
5. **PRD 有三个读者：工程、评测、运营。** 标准：三类人都能在文档里找到自己那一节。代价：只写给工程看，上线当天运营会现编话术。

## 四、上手：30 分钟填出「最小可评审版」

只填 5 节，其余标 TODO 就能上评审会。

1. **（8 分钟）① 目标与非目标 + ③ 能力边界。** 目标必须带一个数字；拒答至少 5 条。
2. **（8 分钟）⑤ 工具清单。** 每个工具写三件事：什么时候用、什么时候不要用、空结果返回什么。
3. **（7 分钟）⑥ 停机与兜底。** max_steps、超时、空结果文案、人工入口在第几屏。
4. **（7 分钟）⑨ 评测与门禁。** 题数、通过线、零容忍项、否决人姓名。

**交付物**：一页 v0.1，含 3 个数字（max_steps / P95 / 单次成本）+ 1 个名字 + 1 条回滚条件。
**验收**：让工程只回答一个问题——「按这份文档，你能开始建吗？还缺哪一行？」缺的那行就是下一版要补的。

## 五、常见误判（反面清单）

| 你会听到的说法 | 实际是什么 | 怎么验证 |
|---|---|---|
| 「PRD 越全越好，11 节都要写满」 | 全而空等于没写；八页没有数字，工程还是要来问你 | 请工程指出「按这份能开始建吗」，指不出就是空 |
| 「工具描述是工程的事」 | 描述里的业务边界（谁能查、查不到怎么说）只有你知道 | 把描述给一个新人看，他能否判断该不该调这个工具 |
| 「兜底就是加个转人工按钮」 | 兜底是「失败后用户看到什么、多久有人接」的承诺 | 空结果、超步数、断网三种情况各走一遍 |
| 「上线标准等有数据再定」 | 数据会替你定一个更宽松的标准，而且是在出事后 | 问「低于多少回滚」，答不出就是没有门禁 |

---

## 六、30 分钟练习

1. 拿一个已上线或在做的 AI 功能，填「最小可评审版」的 5 节（20 分钟）。
2. 补 3 条拒答、1 个否决人姓名、1 条带数字的回滚条件（10 分钟）。

**交付物**：一页 PRD v0.1。
**加练**：给一个没参与的人读，让他指出「哪一句是废话」——那句就是该删或该改成数字的。
