# Agent 产品 PRD 模板

> 用法：直接复制，填空。带 ⭐ 的四节是 Agent 产品**必须有、普通 PRD 没有**的部分——
> 缺了它们，工程会自己拍一个值，而那个值通常不是你要的。

---

## 1. 一句话定义

用一句话说清：**谁、在什么场景下、用它把什么事办完**。

> 例：中小电商客服，在用户咨询售后问题时，用它把「查订单 + 判政策 + 给结论」一次办完，
> 不用再转人工。

反面：❌「做一个智能客服助手，提升用户体验。」——没有主语、没有边界、没法验收。

---

## 2. 为什么是 Agent（而不是模板/工作流）

| 方案 | 能不能做 | 代价 |
|---|---|---|
| A 模板 / 关键词 | | |
| B 工作流（固定步骤） | | |
| C Agent（模型自主决策） | | |

**判定标准**：解决路径能不能事先枚举？
- 能枚举 → 选 B，别选 C（更快、更便宜、更可测）
- 不能枚举，但可以拆成「每步都是固定子任务」→ 选 B + 少量 C
- 完全无法枚举 → 才选 C

⭐ **必须写**：如果选 C，说明「哪一步真的需要模型自己想」。说不出这一步，就退回 B。

---

## 3. 用户与失败成本

| 项 | 内容 |
|---|---|
| 谁在用 | |
| 用错一次，代价是什么 | 说错话 / 用户多等 30 秒 / 造成金钱损失 / 合规风险 |
| 能不能撤销 | 能不能；怎么撤 |

⭐ **失败成本决定一切取舍**：代价高 → 少用 Agent、多加人工确认；
代价低 → 可以激进一点，用体验换效率。

---

## 4. 工具清单（Agent 的手）

| 工具名 | 给模型看的描述（不是给工程师看的） | 入参 | 空结果时返回什么 | 超时 |
|---|---|---|---|---|
| | | | | |

⭐ **描述是产品文案，不是技术文档。** 模型只会照描述去理解这个工具能干什么。
写「查询订单信息」它不知道能查什么；写「按关键词查订单，关键词如『退款』『物流』『发票』」它就会用。

⭐ **空结果返回值必须写死**，例如：
`"没有找到相关数据，请如实告知用户，不要猜测。"`
不写这句，模型会自己编一个。

---

## 5. 循环约束（三个数字）

| 项 | 值 | 理由 |
|---|---|---|
| 最大步数 `max_steps` | 4 | 平均 2 步，留一倍余量；超过 4 步说明想不通 |
| 单次会话超时 | 20s | 用户等待容忍上限 |
| 同一工具重复调用 | 2 次即中止 | 重复 = 卡住 |
| 单次成本上限 | ¥0.15 | 客单价 ¥60，成本占比 <0.25% |

⭐ 这四个数**必须给具体值**。「可配置」= 没人负责，上线后一定是默认值在跑。

---

## 6. 兜底与转人工（用户看到什么）

| 情况 | 用户看到的话 | 之后发生什么 |
|---|---|---|
| 步数用尽 | 「这个我需要人工帮你确认」 | 建工单，2 小时内回 |
| 检索为空 | 「我查不到这部分信息」 | 给相近问题的入口 |
| 工具报错 | 「查询暂时不可用」 | 30 秒后可重试一次 |
| 模型不确定 | 「我不太确定，要不要转人工？」 | 用户选 |

⭐ **兜底文案是产品最高性价比的工作**：一句「没查到，我转人工」，能省掉一整类幻觉投诉。

---

## 7. 不知道的时候怎么办（拒答策略）

- 允许拒答吗：允许 / 不允许（不允许 → 说明为什么必须答，以及答错谁担）
- 拒答率预期：3%–8%（低于 3% 通常意味着它在硬答；高于 8% 说明知识库不够）
- 拒答时说什么：见第 6 节

⭐ **不许拒答的产品，等于要求模型 100% 正确。** 那就别用模型。

---

## 8. 评测与门禁（上线前必须过的线）

| 指标 | 门禁阈值 | 怎么测 |
|---|---|---|
| 召回命中率 | ≥ 85% | 20–50 题人工标注 |
| 忠实度（可溯源） | ≥ 90% | 答案能逐句对回原文 |
| 有用性 | ≥ 70% | 抽样人工打分 |
| P95 延迟 | ≤ 6s | 压测 |
| 单次成本 | ≤ ¥0.15 | 账单 ÷ 请求数 |
| 兜底触发率 | ≤ 10% | 线上埋点 |

⭐ **回归集不许倒退**：老版本的题，新版本一道都不许变差。这条不写，改版就是赌博。

---

## 9. 灰度与观察

| 项 | 值 |
|---|---|
| 灰度比例 | 5% → 20% → 50% → 100% |
| 每档观察多久 | 1 天 / 3 天 / 3 天 |
| 观察哪四个数 | 兜底率、转人工率、用户追问率、单次成本 |
| 谁是**否决人** | 姓名（不是「团队」） |
| 什么情况下回滚 | 兜底率涨 2 倍 / 成本超预算 50% / 出现一次编造事故 |

⭐ **必须有一个人名有权喊停。** 写「由团队评估」的，出事时没人评估。

---

## 10. 不做什么（边界）

明确写出这版**不做**的事，至少三条：

- 不做的场景：
- 不接的系统：
- 不承诺的能力（例：不做价格承诺、不做法律建议）

⭐ 边界写得越清楚，上线越快。没有边界的 Agent 会被用户拿去问任何事，然后以「不好用」收场。

---

## 11. 上线检查清单

- [ ] 第 4 节的空结果文案，已写进代码
- [ ] 第 5 节的四个数字，已写进配置且可观测
- [ ] 第 6 节的兜底文案，产品已逐条确认过语气
- [ ] 第 8 节的评测集已跑过，三项全过
- [ ] 第 9 节否决人已知晓并同意
- [ ] 有一个「一键关掉」的开关（不用发版）

## 附：坏 PRD vs 好 PRD（同一件事）

| | 坏 | 好 |
|---|---|---|
| 工具 | 「接入订单查询接口」 | 「按关键词查订单；空结果返回『没找到，请如实告知』；超时 3s」 |
| 步数 | 「限制调用次数」 | 「最多 4 步；超限回复『我转人工』并建工单」 |
| 拒答 | 「尽量回答用户问题」 | 「查不到就说查不到，拒答率预期 3%–8%」 |
| 上线 | 「测试通过后上线」 | 「召回≥85%、忠实≥90%；5% 灰度观察 4 个数；张三有否决权」 |

差别不在文笔，在于**每一条都能被验证**。
